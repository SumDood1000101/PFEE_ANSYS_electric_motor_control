# Alvik SDK

Bare-metal firmware for the STM32F411 on the Arduino Alvik carrier board, written in C with the STM32 HAL. It replaces Arduino's stock carrier firmware with a minimal, generic interface to the wheels: switch a motor on or off, read its speed, and run a function at a fixed rate. The controller that uses it (for example a model generated by **Ansys SCADE One**) is integrated separately.

The SDK is a small hardware layer. It ports the pin and timer handling from Arduino's [Arduino_AlvikCarrier](https://github.com/arduino-libraries/Arduino_AlvikCarrier) library to plain C, and leaves out the Arduino framework.

## What it does

- **Motors**: switches each wheel's motor driver on (full power forward) or off (coast). A controller can produce a PWM from this on/off switching.
- **Encoders**: reads both wheel encoders through hardware timers in encoder mode, and works out each wheel's speed in rpm every 20 ms.
- **Control tick**: runs a user function 10 000 times a second from a timer interrupt (TIM10).
- **Telemetry**: `main.c` prints the measured rpm of both wheels over USART1 every 100 ms. The motors stay off.

## Integrating a controller

Write a step function that reads the speeds and sets the motors, and register it with `timer_start()` in `main.c` (inside `USER CODE BEGIN 2`, after `alvik_init()`):

```c
static void my_step(void){                      // runs at ALVIK_TICK_HZ, in the interrupt
    for (int m = 0; m < MOTOR_COUNT; m++){
        bool on = /* your controller */ motor_get_rpm((motor_id_t)m) < 30.0f;
        motor_set((motor_id_t)m, on);
    }
}

    alvik_init(&htim10);
    timer_start(my_step);
```

Add the controller's source files and include paths to `CMakeLists.txt`.

## API (`SDK/src/alvik.h`)

| Function | Description |
|---|---|
| `alvik_init(&htim10)` | Turns the motors off, starts the encoders, enables the motor driver and starts the tick timer |
| `motor_set(motor, on)` | `MOTOR_LEFT` / `MOTOR_RIGHT`: `true` drives forward at full power, `false` coasts |
| `motor_get_rpm(motor)` | Wheel speed in rpm, updated every 20 ms |
| `timer_start(callback)` | Calls `callback` on every tick (`ALVIK_TICK_HZ` = 10 kHz), from the interrupt. `NULL` stops the calls |

Rules:
- **Keep the tick callback short.** It runs inside an interrupt 10 000 times a second.
- **No blocking calls in the tick callback**: no UART, I2C or `HAL_Delay()`.
- **Don't define `HAL_TIM_PeriodElapsedCallback` yourself.** The SDK already defines it.

## Hardware

| Function | Pins | Peripheral |
|---|---|---|
| Left motor | PA3, PB3 | GPIO |
| Right motor | PA2, PA15 | GPIO |
| Motor driver enable | PD2 | GPIO |
| Left encoder | PC6, PC7 | TIM3 (encoder mode) |
| Right encoder | PA0, PA1 | TIM5 (encoder mode) |
| Serial to Nano ESP32 | PA9 TX, PA10 RX | USART1, 115200 baud, 8E1 |
| Status LED | PC8 | GPIO |
| Control tick | none | TIM10, 10 kHz |

The SDK configures the motor and encoder pins in code, not in CubeMX. When editing `Alvik_SDK.ioc`, leave those pins unassigned.

Each wheel turn is 900 encoder counts (6 counts per motor turn × a 150:1 gearbox). The wheels are 34 mm in diameter and 89 mm apart.

## Build

You need `arm-none-eabi-gcc`, CMake and Ninja.

```bash
cd Alvik_SDK
cmake --preset Debug
cmake --build build/Debug
```

The output is `build/Debug/Alvik_SDK.bin`. If you move the project folder or regenerate with CubeMX and the build fails, delete `build/Debug` and run the preset again.

## Flash

The STM32 is flashed over UART through the Nano ESP32. The Nano must be running Arduino's `bridge_firmware_updater` sketch, which holds BOOT0 high and starts the STM32 in its bootloader.

1. Reset the Nano ESP32.
2. Close any serial monitor that is using the port.
3. Flash:
   ```bash
   python3 tools/flash_uart.py build/Debug/Alvik_SDK.bin -p /dev/ttyACM0
   ```

The program starts immediately after flashing. Reset the Nano ESP32 again before every flash.
